# Glossary — 项目术语速查（为降低认知负担而设，ADR-0005）

> 按用途分组。每个词一句话说人话。遇到没收录的词：开 Issue 让团队补。

## 流程与治理

| 术语 | 人话解释 |
|---|---|
| **Charter（宪章）** | 项目的最高规则文件；改它要走正式修订（版本号 + ADR）。 |
| **Issue** | 一件要做的事的登记卡（`ISS-001`）；所有工作围绕它展开。 |
| **Milestone（里程碑）** | Game 轨的交付单位（M0、M1…）：一批 Issue + 一个可玩版本 + 一次复盘。 |
| **Wave** | Observatory 轨的交付单位（OW0、OW1…）：比 milestone 更小更快，修 bug 可直通。 |
| **RFC** | 请求评议：要做一个影响多人的决定前，把问题/方案/替代项写下来给大家吵。 |
| **ADR** | 架构决策记录：吵完之后"最终决定 + 为什么"的存档；只增不删，被取代时标记 supersede。 |
| **Supersede** | 用新决定取代旧决定；旧 ADR 不删，加一行"被谁取代"。 |
| **Decision Capsule** | 小决定的轻量存档：单模块内、可逆的决定，不用兴师动众写 RFC。 |
| **Spike** | 用最小代码验证一个假设的限时实验，产出是证据不是产品。 |
| **PR（Pull Request）** | "我改完了，请别人审查后再合入主线的"请求；本仓库用本地分支 + `docs/reviews/` 工件模拟。 |
| **Request Changes** | 审查结论之一："有问题，改了再来"。Merge 不是默认结果。 |
| **Gate（门禁）** | milestone 的质量关卡：Intermediate（中途汇合）/ Final（最终出口）；QA 有权宣布 Failed。 |
| **Retrospective（复盘）** | milestone 结束后的对照会：当初预测的疼点哪些真疼了、下一步值得加什么。 |
| **Autonomous Project Decision** | Owner 没裁决但证据充分时，团队自行决策并显式标记，Owner 事后可推翻。 |

## 角色与协作

| 术语 | 人话解释 |
|---|---|
| **Pod** | 一个 Senior + 一个 Junior 组成的小组（如 ver/vic），共享一个领域。 |
| **Orchestrator** | 指挥角色：分任务、管流程、记事件；不写业务代码、不裁决架构。 |
| **Watchpoint** | 每个成员的观察哨：他最敏感、最容易打回别人代码的东西。 |
| **信息局部性** | 成员的私有想法只写自己的档案文件；跨人信息必须走公开载体。 |
| **Socratic（反问式指导）** | Senior 不给答案，用问题引导 Junior 自己想通——默认教学方式。 |
| **direct（直接给答案）** | 教学上的例外动作，必须记录原因，会被统计进"教学债务"。 |
| **Lookup Trail** | Junior 的查证记录：查了什么→来源→可信度→采不采纳。 |
| **Learning Hook** | 🎓 任务的替代交付物：问题/代码/理由/替代方案/练习，供 Owner 重走一遍。 |
| **🎓（hands-on）** | 留给 Owner 亲手实现的任务；v1.1 起"Agent 实现 + Hook"也是合法履行形态（ADR-0005）。 |
| **Guess 模式** | 回放教学：关键节点先问"你会怎么改"，再对照真实做法。 |

## Observatory 与事件

| 术语 | 人话解释 |
|---|---|
| **Observatory** | 观测站：把"这个软件工程怎么长出来的"做成可视化的产品。 |
| **Event Log** | 事件日志（`observatory/data/log/*.jsonl`）：项目历史的唯一事实源，一行一条、只增不改。 |
| **Envelope（信封）** | 每条事件的公共外壳字段：seq/ts/type/actor/refs/payload。 |
| **seq / logical_seq** | 全局序号（审计用）/ 某次 Run 内的逻辑序号（回放排序用）。 |
| **append-only** | 只追加、永不改写历史——日志可信度的根基。 |
| **checkpoint（快照）** | 阶段末的存档：当时的 git、Issue 状态、模块图、指标，供 Time Machine 对比。 |
| **Worklog** | 成员的人类可读叙事日志（技术密度高、允许写困惑）。 |
| **Fixture** | 假数据：UI 里为"还没有事件源"的视图占位的样本，必须标记且默认隐藏。 |
| **Projection（投影）** | 从事件日志重放推导出的视图；只读，永远不改日志。 |
| **Ambient** | 成员的氛围事件（吐槽/自嘲）；必须锚定真实活动、不含技术事实、默认被 Gate 过滤。 |

## 工程（当前阶段用到）

| 术语 | 人话解释 |
|---|---|
| **WorldGraph** | 房间与连接关系的逻辑图——"世界真实的样子"；玩家看到的画面是它的投影。 |
| **投影（场景侧）** | `build_scene`：把图变成几何盒子。单向：改图→重建画面。 |
| **version()** | 图的改版计数：变了才重建画面，没变就复用。 |
| **失效（invalidation）** | 容器扩容后，指向它内部的指针/引用变成悬垂、不可再用。 |
| **借出规则** | "你可以借用内部的引用，但任何 mutation 可能让它失效"的文档化契约。 |
| **InputFrame** | 一帧输入的快照结构：真人键盘鼠标和 smoke 脚本都填它，游戏逻辑只认它。 |
| **确定性（determinism）** | 同输入必同输出；smoke 连跑 5 次逐字节一致就是它的证明。 |
| **调用面（call surface）** | 允许调用某个库的文件白名单（如 raylib 只许在 main.cpp/scene.cpp）。 |
| **疼痛点（pain point）** | 预先登记的"这里将来会疼"预测，复盘时对账：真疼了才配得到重构。 |
