# Milestone 1 — 看得清的世界（A World You Can See）

- Created: 2026-09-06（Owner v0.1 review 后）· Status: open · Target release: `v0.2`
- 节奏：Game 轨 milestone 模式（ADR-0005）；Observatory 轨问题走 OW0.1 wave（另列）。
- **M1 主题来自 Owner 实测**：B1–B3 通过，但"世界基调为黑色且卡顿严重，无法看清是否瞬移或突变"——B4/C3/D3 因视觉质量被阻塞。**看不清的世界不是一个可验收的世界。**

## 开工三问（charter §18）

1. **游戏真正需要什么？** 玩家能看清空间结构、察觉突变、感知速度——对比度、清晰度、帧节奏是"可玩"的隐形门槛。
2. **当前架构能否支持？** 能。raylib 调用面已收敛（ADR-0002），视觉改造不触碰架构；性能问题必须先量化再动手（P1：压力驱动抽象的反面——压力驱动**修复**，但同样要证据先行）。
3. **哪里会疼？** 预登记：① DrawText 小字号在 raylib 默认字体纹理过滤下发糊（"模糊"的头号嫌疑，其次才是 DPI）；② 帧率问题归因可能是三选一（逐帧 DrawCube 无批处理 / DWM 合成 / dt 节奏）——先上 frame-time 计时与三档对比实验；③ 音频一进来 realtime 边界就从第一行代码被考验（Kai 的红线）；④ 内容外置会第一次让"数据格式"成为跨模块契约。

## M1 验收标准（DoD → v0.2）

1. Owner 重跑人肉 checklist：B4/C1–C5/D1–D4 全部可判定并通过（B1–B3 已通过不重复）。
2. **帧率**：正常模式在开发机稳定 60fps，smoke 路径帧时间分布被记录（p50/p95）——先有数据，后有优化。
3. **对比度/清晰度**：房间、墙、门洞在截图中可一眼区分；文字清晰（诊断文档记录模糊根因与修复选择）。
4. **视觉差异化**：每个房间有可辨识的主题（至少色彩/亮度级），突变 cue 增强到"不看说明书也能察觉"（Owner 判定）。
5. **音乐初步**：进入游戏有氛围性音乐循环；突变瞬间有音频 cue；音乐节拍信息存在于某处但**不强制驱动玩法**（先出生，后生长）。realtime 边界红线自第一行生效（RFC-0005 前置）。
6. **内容外置**：WorldGraph 数据（房间+连接+突变规格）从 C++ 字面量迁到启动时加载的数据文件；smoke 全绿不变（数据外置不改行为——由确定性回归证明）。
7. tag `v0.2` + metrics snapshot；R-002 复盘。
